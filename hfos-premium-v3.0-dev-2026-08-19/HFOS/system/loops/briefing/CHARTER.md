# Morning Briefing — Charter

_A daily coaching surface, within two pages, that directs attention, energy, and action toward what matters most. The only loop that writes for the person._

## Mandate

The briefing is where the system becomes usable each morning: what needs them, what is ready to release, what the day already contains, and what the system needs answered. It is a **coaching surface, not a task report** — it convenes the coach lens once and writes in one calm, unified voice.

Its discipline is **subtraction.** The momentum room runs wide; the briefing targets one page and never exceeds two. Reading is not listing — it renders what earns the space and counts the rest in a line. A briefing that grows into a report gets skimmed, and a skimmed briefing is worse than none.

It is also the loop that makes the **human judgment call on waiting work**: when a check date lands, whether the thing released or became a chase is decided here, where a person is about to read the answer.

**It orients; it does not decide.** It never converts a recommendation into a commitment, never adds to the person's lists on their behalf, and never manufactures urgency.

## Schedule

| | |
|---|---|
| **Default** | **On demand** — "Run my morning brief" (`system/automations/morning-brief-on-demand.md`). No cron at install |
| **Optional later** | A daily scheduled run, only after manual runs feel right — the schedule holds a pointer to this folder, never a copy |
| **Budget** | 15 minutes. Prefer a shorter briefing over a later one |

## Permissions

**May:** read every room in the tree; read mail and calendar **if** `connections.md` lists them connected; write `system/memory/briefings/YYYY-MM-DD-morning.md`; move a due waiting entry to `momentum/BLOCKED.md` per the runbook's step 7.

**Reveal ceiling:** the briefing's only audience is the operator, so it may read what the runbook names (including person files for the day's meetings) — but its render never quotes care material or `life/` content as intelligence; those shape tone only. If a briefing is ever shared onward, it goes through `system/skills/reveal-check/` like any outbound draft.

**Never:** send, publish, spend, or commit anything · add to `momentum/NEEDS_ME.md` anything the person did not put there · render a waiting entry whose check date has not arrived · restate one item under two headings · touch `foundations/` or `life/`.

## Fail-closed behaviour

An unreachable connector is a **named gap** in the briefing, not a silent omission. A pointer that cannot be resolved is named and its section skipped — never reconstruct what a missing file probably said. If this runbook itself cannot be read, write a briefing stating that and stop.

## Stop condition

Today's briefing is written, fits within two pages (120 lines), and carries every open question. Or the budget is reached — the briefing ships as it stands with one line naming what was not gathered. **A run never ends without a briefing file.**
